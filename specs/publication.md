# Discovery and consistent releases

`GET /manifest.jsonld` is the LC2-alpha entry point. Fetch it once per query and retain its `releaseId`. The immutable copy is `/releases/<releaseId>/manifest.jsonld`. Paths/relative IRIs resolve against the manifest response URL; follow the supplied references instead of constructing filenames. The synthetic `demo-lc2-alpha` release uses this same contract.

The [complete example manifest](examples/manifest.jsonld) is generated from the fixtures. Required core properties are `@context`, `@id`, `@type: Timetable`, `schemaVersion: 2-alpha`, `releaseId`, `timeZone`, the `stops` / `trips` / `routes` IRI strings, and `connections: ConnectionCollection`. `transfers` is an IRI string and can be omitted only when there are no rules. License/rights and coverage are recommended; this provider supplies both. There are no bare `files`, hashes, row counts, capabilities or raw ID properties in the LC core.

## Page list and iRail catalog

`connections.pages` lists each page once. Entries have `@id` and this provider also supplies numeric `epochSeconds`, ISO-8601 `minDepartureTime` / `maxDepartureTime`, `region` and `arrivalRegions`. Regions are IRIs, matching `stops.regionIri`. Bounds are inclusive actual departure bounds; coverage is half-open. For query departures `[from,to)`, a page intersects when `maxDepartureTime >= from && minDepartureTime < to`. Equal departures can cross pages, and scans merge all relevant regions. Arrival offsets may exceed a page's bucket or coverage end.

The namespaced `irail:extensions` link points to `/releases/<releaseId>/irail.json`, documented in the [iRail profile](irail-profile.md). That manifest pins source provenance, capabilities, service-date coverage, partition policy and the identity strategy. Its `files` catalog holds integrity descriptors for all core and extension IPC files: `path`, `rowCount`, `byteLength`, lowercase SHA-256 `sha256`, `mediaType`. Hashes/lengths describe final decoded file bytes. Do not restore descriptor objects to LC reference-table properties or undeclared descriptor terms to the LC context.

Validation rejects orphan indices, missing required values, incorrect types/nullability/order, negative/overflowing offsets, inconsistent page epochs/regions, unsorted departures, arrival before departure, duplicate connection keys and catalog bounds/hashes/counts inconsistent with bytes. Stop hierarchies must be acyclic. Transfer types 0–3 require stops; type 2 requires a duration; types 4/5 require both trips and allow null stop selectors. Verify stable IRI relationships in side tables against the same core dictionaries. Raw ID uniqueness and source-generation matching are checked in the iRail profile.

## Planned publication and HTTP

Build all planned data in Node/GitHub Actions and serve it directly through GitHub Pages. Assemble the new immutable release, retained old releases and latest discovery as a complete validated site snapshot. A failed build keeps the previous deployment. Each deployment must include retained paths explicitly; never assume omitted files survive. Retain releases for client/cache/live-generation lifetimes and rollback, within a measured site-size budget. The Actions workflow ([publish-planned.yml](../.github/workflows/publish-planned.yml)) and the Node pipeline (`scripts/build-sncb.mjs`, `assemble-pages.mjs`, `restore-pages.mjs`, `validate-release.mjs`, `check-pages.mjs`) implement this; `npm run fixtures` still generates the synthetic fixtures.

The site root is `manifest.jsonld` (latest), `releases/index.json` (format `irail-cdn-site`: prefix, latest release, retention policy and, per retained release, the byte size and path/length/SHA-256 of its manifest and `irail.json`), `index.html`, `.nojekyll` and `releases/<releaseId>/…`. The index is the trust root used to restore retained releases into the next deployment; each restored file is additionally verified against that release's integrity catalog. Retention is bounded by `config/sncb.json` (`maxReleases`, `maxSiteBytes`); a new release that does not fit fails the build and the deployed site stays as it is.

All final release URLs identify fixed bytes. Discovery may change; never reuse a release ID for different bytes. CDN propagation does not remove the need to pin one manifest/dictionary generation. On a mismatched page or overlay, discard the query's mixed state and restart against one release. Publishing latest pointers across the static and live origins is not an atomic transaction.

Serve resources through GET/HEAD with `Access-Control-Allow-Origin: *`. JSON-LD uses `application/ld+json`, Arrow IPC uses `application/vnd.apache.arrow.file`, and native GTFS-RT uses `application/x-protobuf`. Mutable discovery should revalidate quickly; immutable files should cache for a long time. Check native Pages headers/CORS/cache behavior before claiming production conformance. The optional local Worker fixture adapter supports the new `/manifest.jsonld` and `/releases/...` paths; it is not the planned production origin. There is no old static manifest compatibility alias. R2 remains for the live service.

## Overlay discovery

`/realtime/manifest.json` uses `format=irail-cdn-realtime`, `version=1`, `sourceId`, `sourceIri`, `providerIri`, inline effective `identityStrategy`, `fetchedAt`, numeric `feedTimestamp`, `incrementality=FULL_DATASET`, `staticReleaseId`, and `tripUpdates` (`path`, `byteLength`, `sha256`, `mediaType`). The current collector uses `staticReleaseId: null` because it only archives bytes. That is **not proof of compatibility** with the static release: consumers must match raw GTFS identifiers and fail or expose unresolved entities when the source generations differ. Source/provider metadata uses the configured identity strategy; protobuf IDs themselves are preserved unchanged.

Future normalized Arrow overlay manifests must have a non-null `staticReleaseId` and per-source observation/expiry bounds, attribution and coverage. Numeric indices require matching releases; canonical IRIs permit reconciliation across releases. Raw protobuf is tied to the upstream GTFS ID namespace, not to our integer row numbers. Other overlay families (composition/occupancy/alerts/status) should get their own immutable snapshot objects and discovery manifest, so one source's failure cannot suppress healthy sources. `/feed` supplies an independent twelve-hour observation log; its members reference the same public entity IRIs, not Arrow page offsets.
